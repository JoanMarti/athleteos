# AthleteOS

> A full-stack sports intelligence platform for endurance athletes.

Unifies data from **Strava, WHOOP, Garmin, Suunto, Wahoo, Intervals.icu and TrainingPeaks** into a single dashboard with a rule-based recommendation engine, daily readiness score, ATL/CTL/TSB analysis, and evidence-based training plans across four athlete levels.

## Features

### Authentication
- Email and password with confirmation link
- Social login with **Google** and **Apple** via Supabase Auth
- Route protection via Next.js middleware
- Five-step onboarding wizard on first sign-up

### Daily Dashboard
- **Readiness score** (0–100) calculated from HRV, sleep, training load (ATL/CTL/TSB) and recovery trend
- Daily recommendation generated by a nine-rule priority engine
- Last activity summary with heart rate and power zone distribution
- Weekly load progress: planned TSS vs. actual
- Orientative nutritional estimate (calories, macros)
- Automatic insights: overtraining risk, PRs, aerobic efficiency changes

### Weekly View
- Planned vs. actual load chart by day (Recharts)
- Visual weekly plan grid with session type and TSS per day
- Sport breakdown: cycling, running, swimming, strength
- 30-day ATL/CTL/TSB trend chart

### Recovery
- 30-day HRV trend (RMSSD) with rolling average
- 14-night sleep phase chart (deep, REM, light, awake) as stacked bar
- Recovery score history with green/amber/red banding

### Athlete Profile
- Performance metrics: FTP, LTHR, threshold pace, max HR, resting HR, W', VO₂max, weight, height
- **Power zones** calculated automatically from FTP using the Coggan seven-zone model
- **Heart rate zones** calculated from LTHR or max HR using the Friel five-zone model
- Live W/kg readout as FTP and weight are entered
- Goal manager with seven goal types: FTP, race preparation, aerobic base, time target, fat loss, VO₂max, general fitness
- **Athlete level selector** — four levels (Recreational, Amateur, Semi-Pro, Professional), each with evidence-based training protocols and nutrition targets

### Integrations Panel
- Connection status for each provider with colour-coded indicator
- Manual sync button and last-synchronised timestamp
- OAuth 2.0 for all providers; tokens encrypted with AES-256-GCM before storage
- API Key connection for Intervals.icu (no OAuth required)
- Real-time Strava webhook listener (new activity → synced in under five seconds)

### Responsive Layout
- **Desktop**: fixed left sidebar (240 px)
- **Mobile** (≤768 px): sidebar hidden, fixed bottom navigation with five tabs

```
┌─────────────────────────────────────────────────────────┐
│                    Vercel (Edge Network)                 │
│  ┌─────────────────────────────────────────────────┐    │
│  │              Next.js 15 App Router              │    │
│  │                                                  │    │
│  │  /(auth)        /(app)          /api             │    │
│  │  login          dashboard       integrations/    │    │
│  │  signup         week            metrics/         │    │
│  │  onboarding     recovery        recommendations/ │    │
│  │                 activities      webhooks/        │    │
│  │                 profile                          │    │
│  │                 training                         │    │
│  │                 nutrition                        │    │
│  └──────────────────────┬──────────────────────────┘    │
└─────────────────────────┼───────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          │               │               │
    ┌─────▼──────┐  ┌─────▼──────┐  ┌────▼─────┐
    │  Supabase  │  │  Strava    │  │  WHOOP   │
    │ (Postgres  │  │  API v3    │  │  API v1  │
    │  + Auth    │  │  + webhook │  │          │
    │  + RLS)    │  └────────────┘  └──────────┘
    └────────────┘
```

**Data flow:**
1. User connects a provider → OAuth callback → token encrypted and saved to Supabase
2. Strava sends a webhook when an activity is created → `/api/webhooks/strava` → automatic sync
3. WHOOP syncs recovery and sleep on demand or daily
4. `/api/metrics/calculate` computes ATL/CTL/TSB/Readiness from saved data
5. `/api/recommendations/generate` evaluates nine rules and saves the day's recommendation
6. Dashboard reads calculated data from Supabase via Server Components

## Supabase Setup

### 1. Create a project

Go to [supabase.com](https://supabase.com), create a new project, and note these values for `.env`:

- **Project URL** → `NEXT_PUBLIC_SUPABASE_URL`
- **anon / public key** → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- **service_role key** → `SUPABASE_SERVICE_ROLE_KEY` (Settings → API)

### 2. Run the schema

In the **SQL Editor** of your Supabase project, copy and execute the full contents of:

```
supabase/migrations/001_initial_schema.sql
```

This creates all tables, indexes, RLS policies and the trigger that auto-creates an athlete profile on sign-up.

### 3. Configure social login providers (optional)

In your Supabase project → **Authentication → Providers**:

**Google:**
1. Enable Google
2. Create OAuth credentials in [Google Cloud Console](https://console.cloud.google.com) with the redirect URI `https://YOUR-PROJECT.supabase.co/auth/v1/callback`
3. Paste the Client ID and Client Secret into Supabase

**Apple:**
1. Enable Apple
2. Requires an Apple Developer account
3. Create a Services ID at [developer.apple.com](https://developer.apple.com) and add Supabase's redirect URI
4. Paste the credentials into Supabase

## Integration Setup

### Strava

1. Go to [strava.com/settings/api](https://www.strava.com/settings/api)
2. Create an application
3. Set **Authorisation Callback Domain** to `localhost` for development or your domain for production
4. Copy **Client ID** and **Client Secret** to `.env`

To register the webhook in production:
```bash
curl -X POST https://www.strava.com/api/v3/push_subscriptions \
  -F client_id=YOUR_CLIENT_ID \
  -F client_secret=YOUR_CLIENT_SECRET \
  -F callback_url=https://your-domain.com/api/webhooks/strava \
  -F verify_token=YOUR_WEBHOOK_VERIFY_TOKEN
```

### WHOOP

1. Request access at [developer.whoop.com](https://developer.whoop.com) — approval may take a few days
2. Create an OAuth application
3. Set the redirect URI to `http://localhost:3000/api/integrations/whoop/callback` (dev) or your domain (prod)
4. Copy credentials to `.env`

### Intervals.icu

No OAuth required. Users enter their API key directly in the integrations panel:
1. Go to intervals.icu → Settings → Developer Settings
2. Copy the API Key
3. In AthleteOS → Profile → Integrations → Intervals.icu → Connect

### Garmin, Suunto, Wahoo, TrainingPeaks

These providers require manual approval:
- **Garmin Health API**: [developer.garmin.com](https://developer.garmin.com/health-api/overview/) — commercial approval required
- **Suunto**: [www.suunto.com/api](https://www.suunto.com/api)
- **Wahoo**: [developers.wahooligan.com](https://developers.wahooligan.com)
- **TrainingPeaks**: [developer.trainingpeaks.com](https://developer.trainingpeaks.com) — partner approval required

## Athlete Levels

The sports science engine defines four levels, each with distinct training protocols and nutrition targets derived from peer-reviewed literature.

| Level | Hours/week | TSS/week | FTP (W/kg) | 5 K pace | CHO hard day |
|---|---|---|---|---|---|
| 🌱 **Recreational** | 3–7 h | 100–280 | 1.5–2.8 | 5:30–7:10 /km | 5.5–7.0 g/kg |
| 🎯 **Amateur** | 7–14 h | 280–600 | 2.8–3.8 | 4:15–5:30 /km | 7.0–9.0 g/kg |
| ⚡ **Semi-Pro** | 14–22 h | 600–1 000 | 3.8–4.8 | 3:15–4:15 /km | 8.0–10.0 g/kg |
| 🏆 **Professional** | 22–40 h | 1 000–1 800 | 4.8–6.5 | 2:30–3:15 /km | 8.0–12.0 g/kg |

### Training polarisation by level

| Level | Easy (Z1–Z2) | Moderate (Z3) | Hard (Z4–Z5) | Source |
|---|---|---|---|---|
| Recreational | 80 % | 10 % | 10 % | Seiler (2010) |
| Amateur | 75 % | 10 % | 15 % | Issurin (2010) |
| Semi-Pro | 70 % | 10 % | 20 % | Stöggl & Sperlich (2014) |
| Professional | 80 % | 5 % | 15 % | Mujika & Padilla (2003) |

## Recommendation Engine

Nine rules evaluated in priority order — the first match produces the day's session:

| Rule | Condition | Session generated |
|---|---|---|
| R001 | TSB < −35 or ≥ 6 consecutive high-load days | Complete rest (mandatory) |
| R002 | Readiness < 35 or label `rest_day` | Active recovery only — Z1 (40 min) |
| R003 | Friday + 3 or more hard days that week | Deliberate unload — Z2 (45 min) |
| R004 | ≤ 2 weeks to race (goal: `race_preparation`) | Tapering protocol |
| R005 | Readiness < 55 or TSB < −15 | Aerobic endurance — Z2 (70 min) |
| R006 | Readiness ≥ 70 + FTP goal + FTP set | Threshold intervals 5 × 8 min — Z4 |
| R007 | Readiness ≥ 70 + race goal + TSB > −10 | VO₂max efforts 6 × 3 min — Z5 |
| R008 | Weekend + Readiness ≥ 75 | Long ride or run — Z2 (150 min) |
| R009 | Default | Moderate aerobic — Z2 (60 min) |

**Readiness formula:**
```
Score = HRV component      × 0.35
      + Sleep component     × 0.30
      + Load component      × 0.25   ← derived from TSB
      + Recovery trend      × 0.10
```

**TSB interpretation:**

| TSB | State | Recommendation |
|---|---|---|
| > 10 | Fresh | High-intensity work appropriate |
| −10 to 10 | Balanced | Normal training |
| −20 to −10 | Loaded | Reduce intensity |
| < −20 | High fatigue | Recovery priority |
| < −35 | Critical | Force rest (R001) |

## Security

### Token encryption

OAuth access and refresh tokens are encrypted with **AES-256-GCM** before being written to the database. They are never stored in plain text and are never exposed to the client.

```bash
# Generate a 32-byte (64-character hex) ENCRYPTION_KEY
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### Row-Level Security

RLS is enabled on every Supabase table. Each user can only read and write their own rows, even if the public `anon_key` is used directly.

### Route protection

Next.js middleware validates the Supabase JWT on every request to `/app/*` and `/onboarding`. Unauthenticated requests are redirected to `/login`.

### Database trigger

The athlete profile is created automatically via a PostgreSQL trigger on sign-up, so the `service_role_key` is never exposed to the browser.

## Deployment

### Vercel (recommended)

1. Connect the repository at [vercel.com](https://vercel.com)
2. Set **Root Directory** to `apps/web` in Vercel → Settings → General
3. Add all environment variables from `.env.example` in Settings → Environment Variables
4. Vercel detects Next.js automatically and configures the build

Update the following for production:
```env
NEXT_PUBLIC_APP_URL=https://your-domain.com
```

Update the **redirect URIs** in each OAuth provider dashboard to point to your production domain.

`vercel.json` (in `apps/web`):
```json
{
  "version": 2,
  "framework": "nextjs",
  "buildCommand": "next build",
  "installCommand": "npm install",
  "outputDirectory": ".next"
}
```

> **Important:** The Root Directory must be set in the Vercel UI (Settings → General → Root Directory: `apps/web`), not inside `vercel.json` itself, as the latter causes build failures in monorepo setups.
